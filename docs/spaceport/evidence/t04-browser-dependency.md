## Reachable graph

- `crates/sheprd-gpui/src/browser.rs` wires web pages, visual annotations, page notes, native WebKit/WebView2 views, editor/review/code tabs, tab layout and saved tab state. `browser/{view,native,annotate_view,feedback,store,location}.rs` and its platform modules reach window startup/ticks (`app.rs`, `window.rs`). `remote_browser/{install,window}.rs` installs a Herdr metadata shim and consumes remote page requests; it uses the browser tab path on macOS/Windows and system opening on Linux.
- The private CLI/control surface includes `browser open/reload/feedback/list/navigate/back/forward/text/screenshot/zoom`, tab operations and note delivery (`control/client/browser.rs`, `control/server/{browser,tabs}.rs`, `crates/sheprd-control-protocol/src/protocol/{app,tabs}.rs`, `protocol.rs`, `docs/cli.md`). The command catalog includes New Browser Tab, Toggle Annotate and Install Browser Skill (`crates/sheprd-commands/src/lib.rs`). `agent_skill.rs` bundles `skills/herdr-gpui-browser/SKILL.md`; its shared upstream install path/marker cannot prove ownership of a pre-existing personal skill.
- Browser-owned settings include `open_links_in = "browser-tab"`, tab persistence, code/editor web URLs and browser-skill installation (`config.rs`, `app.rs`, `settings_window/pages/general.rs` and `agent_skill.rs`). Browser/annotation messages and resources span `crates/sheprd-gpui/locales/*/{browser,browser-notes,remote-browser,commands,settings-general}.ftl`, `browser/{bridge,favicon,kit}.js`, `browser/kit/kit.css`, and the GPUI README. `wry` and `objc2-web-kit` in the root and GPUI Cargo manifests are webview dependencies; the terminal link parser's `url` dependency also serves retained URL handling. CLI smoke tests still assert the browser command (`scripts/release/smoke-cli.py`).
- Retained service opening crosses this graph: `listening_ports/{scan,render}.rs` and `port_forward.rs` use `browser::WebUrl`; `listening_ports/render.rs::open_port_link` starts a tunnel when needed and calls `browser/view.rs::open_workspace_page`; `control/server/hosts/ports.rs::start_open` and `open_forwarded` do the same for `ports open`. `open_workspace_page` opens a webview tab on macOS/Windows and calls `cx.open_url` only on builds without embedded pages. `remote_browser/window.rs::open_remote_page` has the same platform split. Removing `browser` or merely switching off its webviews would break or misstate this retained route.
- Ordinary external actions must remain: `terminal/links.rs` and `terminal/links/external.rs` parse bounded URLs and local paths; `menu/open_link.rs` confirms untrusted schemes before `cx.open_url`; `chat/page.rs` has a system file opener on non-embedded builds. The browser's `LocalFile` is currently also used by chat HTML pages, so file handling needs its own retained/excluded split. Browser cookie reads in `sheprd-usage` are a separate provider feature, not evidence of an embedded view.
