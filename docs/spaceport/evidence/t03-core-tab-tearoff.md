# T03: exact Core group tab tear-off

Source base: integration `aab7672f9`. A Core-only group has no legacy endpoints. `window/tab_tear.rs` called `browser_key()`, which returns `None` for a selected Core group, so an outside tab drop did nothing. A new headless drag test first failed because its `TornOff` count was 0 instead of 1.

The handoff now carries either the legacy target/host/session or the exact `CoreGroupKey` and current observation epoch. For Core it accepts only a page tab stored in that selected, fresh group. The existing Core-only additional-window constructor rechecks the group and joins the installed Core with `Start::Join`; the tear-off path creates no legacy endpoint. At arrival, the destination checks its selected group, observed epoch and tab ownership before it changes its visible tab list. A stale arrival returns the tab to the source and closes the destination window. A valid arrival shows the carried tab, hides the other group tabs only in that window, and gives the carried tab back when that window closes. No terminal process, document or Core repository is changed by this view operation.
