# T04/RM-GIT: checkout URL and Windows jump list cut

Base: integration `4e9355c9c`. The app accepted `spaceport://open?path=...` from an untrusted OS link, checked for a local Git checkout or worktree, then focused a legacy workspace or offered to create one through `ask_to_open_checkout`. Windows also published those URLs as recent checkout jump list entries and persisted them in `jump-list.json`. This bounded cut removes the parser variant, checkout probe, dialog and workspace request, recent checkout publication/state, locale keys, current documentation, and obsolete screenshots. It leaves the user's existing `jump-list.json` file untouched; the app no longer reads or writes it.

Retained routes are `spaceport://device?id=...` and `spaceport://notification?tag=...`, including strict parsing, deferred device loading, notification lookup, and exact `--window` targeting. Windows still publishes device tasks. External file/URL terminal interactions are separate and remain. The explicit `spaceport open PATH` CLI route still exists at `control/client/open.rs` and `control/server/app.rs` (`AppOp::Open`); it needs its own Core ownership and retained file interaction review. Other specialized Git/IDE routes remain, so this does not prove full negative reachability.

TDD: `checkout_links_are_refused_while_device_and_notification_links_remain` first failed on the base: the parser returned `Ok(Open { path: "/tmp/repo" })` rather than `UnknownAction("open")`. After the cut, the `link::` filter passed 63/63 tests, including retained external file/URL link cases and the new notification startup case. The control link filter passed 2/2, including a second parse at the control boundary and an exact missing window ID refusal. A production source search found no `Link::Open`, `OpenCheckout`, `ask_to_open_checkout`, checkout URL string, recent checkout jump list state, or dialog route. The URL string remains only in negative tests.

Local verification on macOS arm64: `cargo +1.99.0 check --locked --offline -p sheprd-gpui --all-targets` passed; the two focused Rust filters above passed. `just check-file-size`, `just check-sorted`, `just format-check`, and `git diff --check` passed. `just check-i18n` still reports the two inherited clean-base findings: `menu/github.rs:760` hard-coded GitHub and unused `browser-no-pages`. Cargo emitted inherited macOS compact-unwind and `block` 0.1.6 future-compatibility notices. Package spec validation and 21 package tests passed. The parser and control tests do not prove Windows shell publication or native UI interaction. No Windows target is installed locally, so Windows COM compilation, jump list behavior, and native UI remain for Windows CI/native QA. No live user environment was changed.

T04 remains `blocked` by G-LINK. A29 remains `not_run` until all excluded Git/IDE routes and ordinary content retention are tested end to end.
