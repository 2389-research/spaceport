# Client provider probe removal

T04/RM-PROVIDERS cut from `431f39a8`. T04 stays blocked on G-LINK; A29 and A30 stay `not_run`. T08 and usage parity remain blocked on G-OBS. This cut did not read a real credential, contact a provider, or change a user's settings.

The normal app no longer loads `KeychainGrants` in `crates/sheprd-gpui/src/app.rs` or calls `Usage::poll` from `window.rs` and `window/monitors.rs`. The Usage section, status bar, and panel no longer offer provider refresh, Keychain Allow, or setup controls (`usage/{section,render,panel}.rs`). Removed app-owned grant persistence in `usage/access.rs`. An unreported reading now says Core has no usage feed in the UI and `spaceport usage` CLI; it does not say zero usage, no account, or no plan. `[usage] show` remains a visibility setting for the unavailable view, not a probe switch. Old provider settings remain parsed but are not live creation or sign-in settings in this interim cut; no config rewrite occurs.

The presentation model, status bar segment and panel rendering for supplied reports, and CLI response shape remain for an eventual authoritative Core feed. `sheprd-usage::Host` and `Shell` still serve other host/system-load/listening-port callers. A source search across `crates/` finds no production caller of `Usage::poll`, `Usage::refresh`, `Usage::allow`, `Probe::new`, or `KeychainGrants` outside `sheprd-usage` itself; the remaining matches outside that crate are unrelated clipboard test probes. `window/construct.rs` constructs `Usage::default()` with no host, entry, or worker. Config reload changes `config.usage` but does not inject readings or call the worker, so an already-running instance of this new build cannot retain provider readings across reload. The provider registry, worker, credential and cookie probe code remain compiled in `sheprd-usage`; this cut removes their app entry points, not their full dependency graph. Full extraction needs the shared host/shell consumers and G-OBS source settled. The inherited `docs/usage-providers.md` is marked as historical implementation notes.

The fixture now uses a distinct unreported/error reading to keep translation coverage without the removed action.
