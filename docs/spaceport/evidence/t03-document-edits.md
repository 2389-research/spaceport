# T03 Core document edit service slice

Source: Spaceport worktree based on `3a7388e89c5a0acdc277aef5eb9213240d2ab14c`; pinned Core `cd12ddd88bc11490228343291dc1096c9ed3bf77`. Core's `api/doc.rs` checks the expected version before it writes and returns `kind: "conflict"` for a stale version. The client already exposes typed `doc.get` and `doc.set`; no workspace RPC was added.

The blocking edit service under `core_terminals/workspace_document` takes a parsed document with Core's version. Create, rename, archive and delete change only the local `spaceport` value. A successful `doc.set` returns the new version and value. Only a typed `doc.set` conflict triggers a reread and one retry: creation requires the new ID still absent; edits to an existing workspace require its complete record, including unknown fields, to match the caller's base. The retry applies the edit to the latest document, preserving disjoint changes and unknown fields. A second conflict refuses. `WriteUnknown` keeps the **attempted CAS version** and original typed Core error as its source, including for the rebased write. It covers timeout, connection loss, malformed success replies and non-definite refusals. Core's pre-send `Busy`, `Unsupported`, `Frame` and `Json` failures, plus the pinned server's pre-write `conflict` and `invalid_params` refusals, stay definite. Nothing retries an unknown write.

The old workspace menu and dialogs still consume `ClientShellSnapshot` and call legacy `workspace.*` methods. They have no Core document target. At this service slice's original commit, the observer's document/version/error had no real workspace UI reader. The narrow next seam was a Core workspace action worker taking a **fresh** observer document/version, calling this service, then letting the one existing Core observer reconcile the resulting document notice. UI work also needed to present stale/invalid-document errors and avoid queueing offline edits. No second document copy or subscription was needed.

The follow-on T03 UI slice now adds that bounded Create reader and worker (`t03-workspace-ui.md`). It also added a scripted service regression: conflict from base version 3, reread at version 7, then timeout on the rebased `doc.set` returns `WriteUnknown { version: 7, source: Timeout(DocSet) }` with exactly two writes. The app-global UI guard uses that attempted version, not the earlier base. Rename, archive and delete still lack retained UI controls.

The safety follow-up models `Core::doc_set` returning `Invalid(DocSet)` after parsing a malformed success value; the earlier classifier treated that error as definite. The new regression failed against that behavior, then passed after the classifier fenced it as `WriteUnknown`.
