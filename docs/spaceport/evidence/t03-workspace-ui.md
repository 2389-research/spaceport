# T03 Core workspace UI slice

Source: isolated `wip/spaceport-t03-ui` branch based on `4c4e514e`. This slice keeps the existing Workspaces sidebar and name dialog pattern. A distinct **Core groups** section reads the app-global Core observation's fresh `spaceport` document. It never reads a legacy workspace snapshot for these rows. A missing, stale or invalid document appears as a loading/connection/error state, not an empty group. The render path shows at most 50 validated labels and a remaining count.

**Connect** joins an already running Core on the Hub worker to load the groups. **New** opens a named dialog and may start an installed Core through the same worker. Create is armed only with a fresh parsed document, a live Core backend, a nonempty committed name and no edit in flight. The action sends one `Edit::Create` with the observed Core version to a worker. The edit service uses `doc.set` CAS and its one safe conflict rebase; the UI does not block or queue an offline action. A successful write does not mutate a local group copy: the Core document notice drives the shared observer refresh. The dialog can close while work continues, and a late error appears as a warning.

The app-global edit guard arms before the worker starts, blocks another edit in any window while that worker can rebase, and lives past the submitting window. The worker settles confirmed results itself. An unconfirmed `doc.set` timeout, lost Core connection, malformed success reply or non-definite server refusal leaves the **attempted CAS version** fenced, including when a conflict caused a reread and second write. The edit service carries that version and the original Core error as a typed source. A worker that stops before reporting stays fenced too. A fresh observer document must advance past the attempted version before another edit can start; a same-version reread does not prove the write failed. Manual recovery requires another trusted Core client to make a confirmed versioned change to the same `spaceport` document; after the observer shows a version past the uncertain write, inspect whether the group landed before another Create. When no such client is available, this slice has no safe in-app same-version recovery. Restarting Spaceport clears only the in-memory guard and is not proof of the write outcome. No automatic retry exists.

The private Core fixtures now set `HC_LAUNCHD_DIRECT` to the immediate test runner PID on macOS. Their `Drop` starts `server stop` against the private socket, waits at most 10 seconds for that exact child, then reaps the exact `serve` child with the same bound and checks stop success before the temporary root drops. A process and temp-root scan after the bounded-stop opt-in run found no `hcedit` or `hcobs` leftovers.

## Core group actions follow-on

Source: isolated `wip/spaceport-t03-actions` branch based on `63221132`. Each fresh Core group row now keeps one compact action control in the retained Workspaces area. Its pointer-anchored menu offers Rename, Archive/Restore and Delete; arrow keys and Enter select the same actions. The menu carries the full workspace UUID. Rename uses the existing name dialog pattern, and Delete requires a separate confirmation showing the group label and UUID plus the fact that terminals keep running. Archive changes only the document flag. All three send the same typed edit to the existing worker, which uses the app-global CAS guard and shared Core document observer. Neither the UI nor the edit service stops a terminal, kills a process or deletes a file.

The menu and dialogs capture the observer epoch and document version before consent. A changed version or reconnect epoch makes a dialog stale even if the numerical version matches. Pending work also captures the exact dialog generation: completion from an old Create or Rename cannot dismiss or write an error into a later dialog of the same page. The worker settles unknown writes in the shared guard even after its window closes. A successful write waits for Core's document notice to update the list; no local grouping copy is patched.

Archive keeps its action menu open until the worker is actually queued. With no live Core, stale facts or a blocked app-global guard, it shows the reason in the menu and sends nothing. Its headless regression first failed because the menu closed on that no-op. Rendering lives in `workspace_ui/render.rs`, separate from the action and guard logic; both files remain under the 1,000-line source limit.

## Core group selection and local terminal membership

Source: isolated `wip/spaceport-t03-membership` branch based on `ef75bd1c`. Clicking a Core group name expands its terminal references under that group; the row action menu still handles group CRUD. The selection is window view state. Member rows come only from the fresh, versioned `spaceport` document. Observed names and available local terminal rows come from the shared Core terminal observation. A lost observation hides the member rows; a missing or remote reference stays visible as unavailable, without starting or restoring a process. The list draws at most 50 groups, 50 references in the selected group, and 50 available local terminals.

The local Core's permanent `hello.core.id` and each unqualified local terminal ID form the document reference. The UI requires the per-window backend ID to match the shared observer ID before offering a local terminal for add or attach. Add/Remove use the existing worker `doc.set` CAS and app-global unknown-outcome guard. The pure reducer rejects duplicate and malformed references and removes only an exact `{core_id, terminal_id}` pair. A definite conflict rebases only if the target group was unchanged. Clicking an observed member opens or reuses a retained Core terminal tab and attaches through its existing worker; it sends no spawn, kill, or legacy workspace mutation. Remote addresses still lack a proven address-to-permanent-machine-ID map in this client, so this slice does not add or attach remote members.
