# T04: page new-window requests leave the app

At integration `b49ad18da`, the remaining production `Store::open` call for a web page was `browser::view::open_beside`. A page's `window.open` or new-window link reached it through `Event::NewWindow`; on macOS, `native::new_window` could first build a linked WebKit popup and `Event::Opened` adopted it into a tab. This cut denies child webview creation, reports the requested address through the bounded event queue, validates it as an HTTP(S) `WebUrl`, and calls GPUI's system URL handler while the source page tab still exists. It keeps the exact requested URL, including query and fragment, and adds no tab. A closed source tab opens nothing. The popup builder, adoption, delegate, close queue, and popup-only error are removed. The existing event capacity remains 64 and a full queue still drops a report rather than growing without bound.

TDD: `page_new_window_opens_exact_url_without_creating_a_tab` failed on the old path because no system URL opened and a tab was added. After the cut, it passed alongside the closed-source case. A native handler unit test asserts `NewWindowResponse::Deny` and the queued URL and source ID. The retained service system-open tests passed 2/2. No real browser, personal URL, user data, or Core repository was used.

Local Rust 1.99.0 checks used isolated `CARGO_TARGET_DIR=/tmp/spaceport-t04-entry-target`, `CARGO_INCREMENTAL=0`, and `CARGO_PROFILE_DEV_DEBUG=0`: the `new_window` test filter passed 7/7, including the two popup view tests and native Deny/event test; service system-open tests passed 2/2; the root-error localization test passed 1/1; and `cargo +1.99.0 check --locked -p sheprd-gpui --bin spaceport` passed. `just format-check`, `just check-sorted`, `just check-file-size`, `just check-i18n`, and `git diff --check` passed. The test link emitted the existing macOS compact-unwind `__eh_frame` warning; Cargo reported the existing `block 0.1.6` future-compatibility notice. The production check emitted no source warnings.

The specification package rendered and checked with `tools/spec.py`; its 21 `tools/test_spec.py` tests passed. An initial generic `unittest discover -s tests` invocation failed because this package has no `tests` directory; the package's actual test entry point is `tools/test_spec.py`.

This is one entry-point cut. `Pages::ensure` and `lb-wry` still compile. The direct dependency also supplies `wry::raw_window_handle` to `taskbar/button.rs`, `window/tab_float.rs`, and `window/backdrop/macos.rs`, while the root error type still wraps `wry::Error`; integration-test smoke page fixtures still exist. Those imports need a separate dependency and feature audit before removing `lb-wry`. The retained rich chat Markdown/math, system URL opener and service links, workspaces, terminals, and file interactions were left in place. Native desktop parity, Windows/Linux builds, full browser graph reachability, and A28 were not run. T04 remains blocked under G-LINK and A28 remains `not_run`.
