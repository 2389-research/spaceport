# T04: chat HTML opens with the system handler

At integration `a13a511b9`, a click on a chat HTML fence or a tool-written HTML file created a `wry` page inside the chat on macOS and Windows. The same click already copied the HTML into an isolated private folder and opened that copy with GPUI's system URL handler on Linux. This cut uses that route on every desktop. The click remains explicit, the copied file remains bounded and private, and a remote tool file is still refused instead of being mistaken for a local file. Chat Markdown, math, code, file links, and image cards stay in the native GPUI renderer.

The cut removes the chat-only webview adapter, live chat page IDs, page placement and settling, and inline HTML preview controls. It does not remove the standalone browser tab store, saved page restoration, native webview modules, browser control routes, or `wry`: those still have reachable paths and need a separate cut. The retained service URL and terminal file/link routes were not changed. No Core route, daemon, personal state, real system browser, or native desktop window was used.

TDD: `requested_html_opens_a_copied_file_without_creating_an_embedded_page` first timed out because the macOS path never called the system handler. After the route change, it observed a `file:` URL whose copied file held the exact HTML and no inline page bounds. It passed after matching the parser's trailing newline. The old test that manually inserted a live chat page was replaced by this negative reachability check.

Focused results, with `CARGO_TARGET_DIR=/tmp/spaceport-t04-embedded-target`, `CARGO_INCREMENTAL=0`, `CARGO_PROFILE_DEV_DEBUG=0`, and Rust 1.99.0: the chat embed filter passed 5/5; rich chat 29/29; private HTML copy 2/2; rich file links 5/5; terminal links 42/42; service system opening 2/2; Core chat presentation 3/3. `just format-check`, `just check-sorted`, `just check-file-size`, `just check-i18n`, and `git diff --check` passed. The package render, schema check, and 21 package tests passed using an isolated `uv` environment with `jsonschema==4.26.0`; the first package-test attempt failed solely because the ambient Python lacked that declared dependency. The GUI test link emitted the existing macOS compact-unwind warning, and Cargo reported the existing `block 0.1.6` future-compatibility notice. Native browser opening, Windows/Linux builds, full workspace tests and A28 were not run. T04 remains blocked under G-LINK and A28 remains `not_run` until the full browser graph and retained parity are proved.
