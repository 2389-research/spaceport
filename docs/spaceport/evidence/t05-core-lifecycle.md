# T05 private Core terminal lifecycle proof

At Spaceport source `f1d3807f`, `crates/sheprd-core-client/src/tests/live/lifecycle.rs` adds one opt-in regression against an explicit Core binary. The binary `/tmp/spaceport-t00-target/debug/herdr-core` reported `hc 0.1.18` and SHA-256 `30eee3cb46bad36ae483c8c459c0ad3acb394089fcf690a9390e1e470196f58b`; `evidence/t00-core-build.log` records its build from read-only pinned Core source `cd12ddd88bc11490228343291dc1096c9ed3bf77`. No personal daemon, agent, socket, home or config was read or changed.

The existing `crates/sheprd-core-client/src/tests/live.rs` sandbox starts only its own Core child with a cleared environment, unique short private HOME/XDG paths and `HC_SOCKET`. It ends the owned terminal with `terminal.kill`, then asks that exact private Core to `server stop` and waits for the children; its drop path also cleans up after an assertion failure. The test uses `sh -c 'printf still-here; sleep 30'` as a fixture program, not an agent.

The first Core client runs and attaches the terminal, then drops the attachment and its connection. `Attachment::drop` sends a stream CLOSE (`crates/sheprd-core-client/src/stream.rs`), distinct from `terminal.kill`. A second Core client lists the same address in `Live` state with the same PID, reattaches, and reads the original `still-here` paint. An attach to a nonexistent terminal is refused; the terminal list has the same addresses before and after that attempt. This proves a local Core terminal survives a client detach and a second client can resume viewing it without starting another process. It also shows that an invalid attach alone creates no replacement terminal.
