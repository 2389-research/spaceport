## Reachable graph

- `crates/sheprd-automate` is the executable that scans approved Luau scripts, schedules and runs steps, stores run state, exposes a JSON command line and installs a user service (`src/{daemon,runner,scan,store,service,cli}`). It enables `sheprd-automation/engine`, which depends on `sheprd-luau`. Since the client-mod cut, automation is the remaining workspace consumer of Luau. GPUI depends on `sheprd-automation` with the engine off for its report types (`crates/sheprd-gpui/Cargo.toml`, `crates/sheprd-automation/Cargo.toml`).
- The GUI's `automations.rs` owns the activity section and reads each reachable local/SSH/cloud host through `automations/hosts.rs` and `fetch.rs`, which invokes `herdr-automate --json` locally or through `teleport::Host` scripts. `SheprdWindow::poll_automations` runs on window ticks and reads every 15 seconds while shown, every 60 seconds otherwise; it also reads when the bar is hidden for notifications and CLI approval. `install_automation_status` can start a host daemon when scripts are listed but none runs. `automations/{actions,dialog,install}.rs` can run, pause, stop, approve and deploy scripts/services. This polling and autostart cannot survive as a hidden passive reader.
- The same report drives sidebar activity counts, badges, run/script pages and timeline, notifications, and log-window sources (`sidebar/activity.rs`, `automations/{section,page,timeline,notify,logs}.rs`, `log_window/source.rs`). `[sidebar] automations` and its Settings switch control that section (`config/sidebar_style.rs`, `config/preferences.rs`). These are presentation paths, but their current data source is the excluded daemon.
- The private desktop CLI parses `automation approve`; the control protocol carries `HostOp::AutomationApprove`, whose server opens a GUI approval dialog (`cli/control/hosts.rs`, `control/{client,server}/hosts`, `sheprd-control-protocol/src/protocol/hosts.rs`, `docs/cli.md`). `agent_skill.rs` still bundles and refreshes `skills/herdr-automations/SKILL.md`, which tells agents to write and check scheduled scripts. Its shared Sheprd marker and `.claude`/`.agents` path do not prove that a file already in a personal home belongs to Spaceport; deleting such a file needs distinct ownership proof.
- `Justfile`, `.github/workflows/{ci,release}.yml` and `scripts/release` still build, sign, package, smoke-test and install `sheprd-automate` on macOS, Linux and Windows. The shared `host_build.rs` and `teleport::Host` also serve other pending feature cuts and cannot be deleted by name with this unit. The old automation skill, docs, English messages, settings, command tests and package tests are reachable or assert these paths.
