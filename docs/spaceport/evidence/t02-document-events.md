# T02 document events and sequence fence

Pinned Core source `cd12ddd88bc11490228343291dc1096c9ed3bf77` emits `event` notifications with `type: "doc"`, `data.name`, `data.version`, and an optional saved-machine `machine`. These notifications have no `terminal` field (`crates/herdr-core/src/events.rs`). The existing client parser required `terminal` for every event, so it rejected document notifications as unreadable and discarded them. This is the root cause of the missing document signal; no Core method was absent.

The parser now yields a typed document notice with its sequence, document name, version and machine. The terminal backend advances its shared event sequence on that notice, so a later stale terminal event cannot undo a newer snapshot or fact. It does not interpret the document or invent workspace semantics. A document reader must use this notice to refetch `doc.get`; `missed` and a new connection still require a fresh read.

The new parser and sequence tests first failed to compile because the notice variant did not exist. After the change, `cargo +1.99.0 test --locked -p sheprd-core-client --lib` passed 46 tests with four ignored. The private two-Core fixture subscribed before writing a remote `spaceport` document and received `machine: "lab"`, version 1 through Core's own event stream; `just test-core` passed all four opt-in tests on macOS. `cargo +1.99.0 check --locked -p sheprd-gpui --bin sheprd` passed with the pre-existing `block` future-compatibility notice. This is a route and sequence proof, not A53 acceptance: the app has no watched presentation-document projection or reconnect refetch yet. Native Windows and Linux have not run.
