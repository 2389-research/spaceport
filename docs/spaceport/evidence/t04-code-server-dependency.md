# VS Code server removal boundary

Read-only source audit at `da3bcf7f`. T04 and RM-IDE remain `in_progress`; A29/A30 remain `not_run`. No VS Code process, SSH host, server, network address, personal config, or Core state was accessed or changed.

## Reachable paths

- `crates/sheprd-gpui/src/app.rs` installs both `code_server::Launcher` and `code_server::Hosts` on normal startup. `code_server.rs` and `code_server/{cli,token,launcher,supervisor,host,machine}.rs` find the local VS Code CLI, keep a token, run/restart `code serve-web`, and run/download its CLI on an SSH host via `host/serve.sh`. The probe and settings address mode use `browser::WebUrl`. Removing only the install calls would leave the server probe, address mode, tabs and commands reachable.
- `browser/{code,code_group,code_host,code_start,code_view}.rs` opens and polls VS Code pages. `browser/view.rs` holds local and host server state and calls `ensure_code_page` on ticks. `browser/editor.rs` dispatches `Editor::VsCode` beside `Editor::Px0`; `browser/store.rs` shares `Place::Editor`, groups and saved tabs with px0 and browser pages. `group_menu.rs`, `menus.rs`, `window/commands.rs`, and `sheprd-commands/src/lib.rs` expose Open VS Code. `control/server/tabs.rs` reports the VS Code tab through the generic tab list; the CLI `code open/edit` and `TabOp::Code/Edit` instead concern the separate read-only source tab and terminal editor and must be audited in their own cuts.
- `config.rs` parses `[code]` mode, URL, port and license acceptance; `config/files.rs` writes it. `settings_window/{section,catalog,controls}.rs` and `settings_window/controls/code.rs` expose it. The Code section also owns px0 settings (`controls/px0.rs`), and selecting the section opens both controls. English messages live in `locales/en-US/{browser-vscode,code-server,settings-code,settings,commands}.ftl`; `settings-code.ftl` also contains px0 messages. `icons.rs` lists `vscode.svg`; `config-gpui.example.toml` and `crates/sheprd-gpui/README.md` document the feature. The server has no separate Cargo crate or package binary; the GUI starts an installed CLI or downloads the host CLI at runtime. Shared `ureq`, `url`, and webview dependencies cannot be removed on this evidence alone.

## Required seam before deletion

`browser/editor.rs` saves VS Code as `"code"` (also accepting `"code_group"`); `browser/store.rs::parse` deserializes the entire saved tab list before `Store::load` restores it. Deleting `Editor::VsCode` without a deliberate filter or state migration makes one old VS Code tab reject the entire file, including unrelated px0/page tabs. `settings_window::Section::Code` cannot simply disappear while px0 settings still use it. A complete cut must settle retained tab/layout ownership and relocate or remove px0 under its own T04 decision; T03's pending view migration is the task dependency already recorded in `plan/tasks.json`. This is a persisted-state and shared-UI dependency, not a reason to keep a disabled code-server worker.

After those seams are set, remove the startup workers, local/host server and script, probe/address mode, VS Code tab/command/menu/settings, config writes, assets, messages, docs and feature tests together. The red check should load saved `"code"` and `"code_group"` tabs beside a retained px0/page tab and prove the retained tab survives while VS Code has no runtime entry; another should reject old VS Code commands/settings and show normal startup creates no launcher or host supervisor. Retained checks should cover px0 settings/tab restore, Core terminal/chat views, and external URL/file opening through `terminal/links` and `chat/view/rich/links`. This audit ran no product tests and does not claim a code cut, native QA, or A29/A30.
