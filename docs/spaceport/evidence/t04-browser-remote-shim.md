# RM-BROWSER: SSH page-request shim

At parent `13dc4573`, `remote_browser` installed a shell `herdr-gpui` shim and a copy of the managed skill on saved SSH hosts through `install_remote_agent_tools`. The shim wrote `herdr-gpui-*` workspace metadata; `SheprdWindow::poll_remote_browser` read it on every tick and created a page tab, starting an SSH loopback forward first when needed. This unit removes that installer, shell asset, metadata reader/Seen ledger, forwarding wait queue, window field/tick hook, and remote-only notices. A headless window test delivered actual old-style tokens through the endpoint inbox and was red before the cut because a Store tab appeared; after the cut they do not create one. The sidebar's pure `herdr-gpui-*` filter remains so legacy tokens never appear as custom values; it does not act on them.

The app never runs a remote uninstall. An existing host may still hold a prior `herdr-gpui` shim or skill copy. Their shared upstream marker and path cannot prove Spaceport ownership, and this repo has no installation receipt. Safe cleanup needs a distinct ownership record or a user-directed action on the exact host. Existing tokens expire individually, but an old shim can continue emitting them until removed by its owner. The app ignores them.

`[agent_skill] install` now accepts `local` (default) and `off`; `local` keeps the existing local offer and refresh. The former `ask` value meant local plus SSH and is rejected rather than silently reinterpreted. A user with an explicit `install = "ask"` must change it to `"local"` or `"off"`; no config is rewritten. The current desktop managed skill has no SSH page-open promise.

Retained `ports open`, listening-port UI, and saved-host forwarding use `open_workspace_page` and `port_forward` independently. Their exact endpoint checks and system URL handler remain. `browser::Store`, saved page tabs, native webviews, visual annotations, page controls, and associated assets/dependencies remain for later coherent cuts. G-PORT still lacks a proved Core forwarding owner; T04/RM-BROWSER remain in progress and A28/A29 are not run. No Core, personal daemon, SSH host, user config, native browser, or service was touched.
