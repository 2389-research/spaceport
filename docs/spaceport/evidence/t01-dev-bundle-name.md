# T01: canonical development bundle name

Base integration `30996ebbf`. The delivered user test app needed a manual rename because `just bundle` still emitted `Sheprd.app` and copied upstream bundle display names. The development recipe now creates `Spaceport.app`, sets `CFBundleName` and `CFBundleDisplayName` to Spaceport, and keeps the existing `spaceport.development` bundle ID. Both native launch recipes use that path. The packaged `spaceport` and `sheprd-acp` executable names and retained icon resources stay consistent with existing callers. Production packaging and signing remain gated.

TDD: three existing recipe/identity tests failed with the required Spaceport path and display names before the recipe changed. After the change, all six `test_app_name.py` tests passed, `just --list` parsed the recipe, and `git diff --check` passed. The tests compare development names to the running app's constants while keeping the inherited production plist and icon resource contract explicit. No runtime or personal app state was changed.

`RUSTUP_TOOLCHAIN=1.99.0 CARGO_INCREMENTAL=0 just bundle debug` built the real bundle using the shared task target. Its plist has the expected Spaceport names, `spaceport.development` ID and `spaceport` executable. The only executable companions are `spaceport` and `sheprd-acp`; no runtime is bundled. `codesign --verify --deep --strict` and the real bundled executable's `scripts/release/smoke-cli.py` check passed. Cargo reported the existing `block 0.1.6` future-compatibility notice. Quick format/file-size/sorted/i18n checks, specification validation and all 21 package tool tests passed.

The bundle was not launched or installed. This proves development artifact assembly and windowless CLI behavior, not native notifications, Dock state, GUI parity or production signing. T01 remains in progress, A42 remains not_run and G-RELEASE remains open. The previously delivered user-test bundle is separate and was not replaced.
