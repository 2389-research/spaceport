# T08 passive observation boundary

Source: Spaceport `d8329703` and pinned Core `cd12ddd88bc11490228343291dc1096c9ed3bf77` (`hc 0.1.18`). The T00 private runtime capture in `evidence/t00-core-runtime.json` contains 32 `rpc.discover` methods. `terminal.list`, `terminal.get` and `events.subscribe` expose live terminal records and ordered changes; there is no named job, provider usage, rate-limit or timeline-history method in that complete method table. This observation is scoped to the pinned version, not a claim about future Core releases.

The new opt-in `crates/sheprd-core-client/src/tests/live/observation.rs` test used the existing `crates/sheprd-core-client/src/tests/live.rs` sandbox: a cleared environment, unique private HOME/XDG paths and `HC_SOCKET`, an exact owned Core child, and two fixture shell programs. One sent OSC 7501 `blocked` with `kind=permission`; a Core status event reported it and `terminal.list` returned it. The other remained live without a status; `terminal.get` and `terminal.list` returned `status: null`. The fixture killed both exact terminals and stopped and reaped its private Core. No personal daemon, account, provider or agent state was used. The focused test passed on macOS with the explicit `/tmp/spaceport-t00-target/debug/herdr-core` binary (SHA-256 `30eee3cb46bad36ae483c8c459c0ad3acb394089fcf690a9390e1e470196f58b`).

Core's `crates/herdr-core/src/{api.rs,terminals.rs,status.rs}` and `schema/README.md` show that status is a program report, not an inferred state. `events.subscribe` sends a current terminal snapshot, changes and `missed` replacement; it is not durable history or global event replay. Spaceport's `crates/sheprd-core-client/src/{wire.rs,event.rs,backend.rs}` already parses those facts, mapping no status to `AgentStatus::Unknown`. `crates/sheprd-gpui/src/core_terminals/observation.rs` keeps an in-memory, epoch-fenced terminal projection. This subset can support current terminal attention, but the native notification path in `crates/sheprd-gpui/src/{state.rs,notifications.rs}` still consumes legacy `SemanticNotification`; no Core status-to-notification scenario has been proved.

The retained automation timeline in `crates/sheprd-gpui/src/automations/{timeline.rs,fetch.rs}` reads `herdr-automate --json` reports; its 15/60-second poll and autostart are documented in `evidence/t04-automation-dependency.md`. The usage status bar/panel reads `sheprd-usage` provider probes and keychain grants through `crates/sheprd-gpui/src/{window/monitors.rs,usage/}`. Both sources are excluded by `SPEC.md` SP-011. Keeping either as a hidden passive reader would violate that boundary. Showing an empty timeline, zero usage or “no jobs” would make unavailable facts look known.

**G-OBS remains open.** Full visibility needs an authoritative, read-only feed for job/schedule/run facts and provider usage/rate-limit facts, with scope, identity, freshness, authorization and bounded history stated. No owner or endpoint for that feed is established; a pinned contract and private scenario must precede a parity claim. T08's retained timeline work and T04's coherent collector/scheduler deletion must then put supported facts on the display and show unsupported sections as unavailable. No independent UI patch here can safely replace the current feeds without touching those paths. T08 is blocked; A18, A19, A20 and A21 remain `not_run` because this fixture covers only local terminal status, not the full acceptance scenarios. A24 and A41 also remain `not_run`.
