# Mobile publication hook removal

Bounded T04/RM-PHONE cut from `14dfb375`. The iOS TestFlight job in `.github/workflows/ios.yml` and local `justfile` recipe were the two upload entry points. Both called `ios/tools/testflight.sh`; that script and its private App Store Connect, build-number and notes helpers had no other callers. This cut removes those routes and their sole support test, plus current upload promises in `ios/README.md` and `docs/ios-app-plan.md`. It does not use an Apple key, sign, archive or upload an app.

The same iOS workflow still runs Swift tests and an unsigned simulator build. The iOS/watch source, XcodeGen targets, branding check and local `ios-generate`/`ios-test`/`ios-build` recipes remain pending T10; this cut does not claim mobile absence. Desktop release and CI still build, sign or bundle `sheprd-remote-control` and `sheprd-nearby` via `.github/workflows/{ci,release,nix}.yml`, `scripts/release`, `justfile`, Cargo manifests and their package tests. Those paths and `device_tags`/Core machine ownership need the separate RM-PHONE seam in `t04-phone-dependency.md`. The private desktop CLI and Core terminal/chat paths were not changed.

The new `scripts/release/tests/test_mobile_publication.py` failed first on the live TestFlight job, then passed after the removal. It asserts that the unsigned iOS check remains and neither upload job, local recipe nor upload scripts remain. The existing desktop release test script passed 11 tests; CI policy passed 9; `actionlint .github/workflows/ios.yml`, `just check-file-size`, `just check-sorted`, and the specification package check passed. `just --list --unsorted` showed the three retained local iOS build/test recipes and no TestFlight recipe; `git diff --check` passed. No iOS simulator, native desktop, phone service, Core or real release run was performed. T04 and RM-PHONE remain `in_progress`, T10 remains `not_started`, and A30/A54 remain `not_run`.
