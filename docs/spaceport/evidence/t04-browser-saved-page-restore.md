# T04: saved browser pages do not reopen

At integration `a13a511b9`, a saved `browser-tabs.json` entry with a web URL, local HTML file, or blank legacy page restored into the tab store. A shown page could then cause `browser::Pages::ensure` to build a native webview. This cut filters those entries at restoration. It preserves Devices tabs, Core terminal tabs, and empty Core group tabs, and reserves every discarded ID so a stale group pick cannot select unrelated content. The parser still validates old entries before the store discards them; no personal file was read or migrated.

The new store test first failed because a web page restored. Its first implementation pass exposed an empty Core group tab with `location: None`; the filter now keeps it by Core scope. The test covers web, local file, blank legacy, Devices, and Core tabs. Existing retired-tab fixtures now use Devices as their retained control so they continue to test ID reservation without depending on an excluded browser page. The saved tab CLI test keeps exact Core and Devices targets and refuses retired IDs.

The preceding chat HTML cut left three production warnings. This cut limits the `LocalFile` re-export and constructor to test fixtures and removes the obsolete dead-code expectation for `chat::page::Error::NotFile`, which the system-browser path now uses on every desktop. `cargo +1.99.0 check --locked -p sheprd-gpui --bin spaceport` passed in the isolated target without those warnings. Cargo still reports the existing `block 0.1.6` future-compatibility notice.

Focused results: the browser store filter passed 20/20; saved tab CLI 1/1; Core workspace UI 21 passed, 3 ignored live cases; Devices overview 30/30; chat embeds 5/5. The test binary link emitted the existing macOS compact-unwind warning. Native desktop restore, Windows/Linux builds, full workspace tests, and A28 were not run. Runtime browser page construction, webview modules, the `wry` dependency, and other excluded browser controls remain for later T04 work. T04 remains blocked under G-LINK and A28 remains `not_run`.
