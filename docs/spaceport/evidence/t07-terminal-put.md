# T07 Core terminal attachment subset

Pinned Core `cd12ddd88bc11490228343291dc1096c9ed3bf77` advertises `terminal.put` for a live terminal on a named machine, with at most 8 MiB of raw bytes encoded as base64. Spaceport commit `be091da9` adds a typed client call that keeps the qualified terminal address, refuses oversized input before dispatch, and returns Core's staged path and byte count without typing into the terminal.

The red compile test preceded the method implementation. `cargo +1.99.0 test --locked -p sheprd-core-client --lib` then passed 52 tests with 4 opt-in live tests ignored. Scripted peer tests assert the exact `lab/t7` target, payload `AP9B` for `[0, 255, 65]`, parsed result, size refusal and unsupported-method refusal. `just test-core /tmp/spaceport-t00-target/debug/herdr-core`, with `RUSTUP_TOOLCHAIN=1.99.0` and the private target directory, passed all 4 opt-in tests. Its two-Core relay fixture staged those three bytes in a remote fixture terminal and read them from Core's returned private path. `cargo +1.99.0 check --locked -p sheprd-gpui --bin sheprd`, formatting, file-size and sorted checks passed. The GUI check emitted only the pre-existing `block` future-compatibility notice.

At `f1d3807f`, an additional opt-in test used one direct private Core and a live fixture terminal. Two `terminal_put` calls with the same `report.bin` name and distinct binary bytes returned separate `report.bin` and `report-2.bin` paths inside that Core's isolated state root. Reading both paths after the second put recovered the original bytes, so this route did not overwrite the first staged file. The test killed its exact terminal and checked private `server stop` and child reaping through the hardened fixture. `HERDR_CORE_TEST_BINARY=/tmp/spaceport-t00-target/debug/herdr-core CARGO_TARGET_DIR=/tmp/spaceport-t07-files-target CARGO_INCREMENTAL=0 cargo +1.99.0 test --locked -p sheprd-core-client --lib a_real_core_stages_distinct_binary_files_for_one_terminal -- --ignored --nocapture` passed 1/1 on macOS. Core's handler at `api.rs:520–538` returns the staged paths and performs no terminal input operation.

This proves a bounded local staging and non-overwrite subset, alongside the prior private two-Core remote staging result. It does not prove real SSH, Windows/Linux, drag/drop, chat attachments, general download, cancellation or replacement safety. The retained UI still calls legacy `sheprd_client::upload_files` from `window/transfers.rs` and `chat/window.rs`; its `port_forward.rs` starts its own `ssh -N -L` child. Neither is a Core-backed parity route. A25/A26 remain `not_run`; G-FILE and G-PORT remain open under [the file route audit](t07-file-route.md).
