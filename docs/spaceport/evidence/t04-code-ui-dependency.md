# T04/RM-IDE: VS Code UI and saved-tab dependency

Read-only audit at parent `9f8421db`. `crates/sheprd-commands/src/lib.rs::OpenCode` is the palette, shortcut and `run open_code` command; `crates/sheprd-gpui/src/window/commands.rs` dispatches it to `browser/code.rs::open_code`, which creates an embedded VS Code editor tab. `crates/sheprd-gpui/src/menus.rs` exposes the titlebar item. `group_menu.rs::Action::VsCode` is a second direct entry that calls `open_code` without the command catalog. `menu/settings.rs` and `locales/en-US/commands.ftl` carry shortcut and label reachability. This command is distinct from the removed read-only `sheprd code open` CLI route and from OpenCode, the agent name in chat content.

Saved editor tabs remain an active route. `browser/editor.rs::Editor::VsCode` reads both `place = "code"` and `"code_group"`; `browser/store.rs::parse` deserializes the entire saved list before `Store::load` installs it in `app.rs`. `window.rs::tick` calls `browser/view.rs::poll_browser`, which calls `ensure_code_page` even without a new command. `app.rs` also installs `code_server::Launcher` and `code_server::Hosts` on normal startup; `settings_window/controls/code.rs` and `[code]` config still configure that path. `browser/store/tests.rs` proves both old spellings restore. A direct UI-entry cut alone leaves the saved VS Code server path reachable; deleting the editor enum before filtering old saved entries could reject the full file and lose retained px0/page tabs.

The separate read-only `Location::Code` tab remains reachable from `code_search.rs`, `security/actions.rs` and saved Store entries: `browser/view.rs::poll_browser` calls `code_view.rs::poll_code_views` to load them. Rich-chat code text and copy in `chat/rich` and explicit system file opening in `window/file_links.rs` are retained. They do not justify keeping the specialized IDE view.

The smallest coherent next cut needs a saved-state rule first: load an old file containing `"code"` and `"code_group"` editor tabs beside px0, a normal page and a Core terminal tab, discard only the VS Code tabs, and keep the rest with stable IDs. `Store::with_tabs` derives `next` from retained IDs, so the filter must also keep new IDs above the discarded maximum or clear saved group picks; otherwise a new tab could take an old VS Code ID. Then remove `OpenCode` from the catalog, shortcut/palette dispatch, titlebar and group menu, followed by the startup/server and settings/config graph when no route calls it. Replace command-driven VS Code tests with a negative entry/reachability test; keep retained tab restore, rich-chat code copy and system file-open checks. The current browser VS Code fixture suites have roughly 1,170 lines across six files and call `OpenCode` directly, so removing the catalog alone would strand tests for a still-reachable saved route. No code deletion, product tests, native UI, Core, personal state or network service was touched. T04/RM-IDE remain in progress; A29 is not run.
