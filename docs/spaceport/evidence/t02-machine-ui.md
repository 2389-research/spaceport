# T02 Core machine catalog in the desktop picker

This change shows a read-only Core machine section in the existing Device picker. The app-global Core observation is the only machine presentation projection: it reads `machine.list` from the connected `CoreBackend`, keeps Core's permanent machine ID with each record, and displays Core's target and connection state without inferring reachability. Core owns the saved catalog and remote connection. The rows offer no legacy Herdr 1 device actions.

`machine.list` is a supported read in pinned Core `cd12ddd88bc11490228343291dc1096c9ed3bf77`; its method is in `schema/hc.openrpc.json` and the Core client checks `hello.methods` before sending. Core's subscription does not advertise a machine catalog event, so one read worker refreshes every two seconds. It stores only the latest result in a one-slot mailbox. The terminal/document observer checks the slot after its 200 ms event drain and never waits for that RPC. Core's 10-second call timeout cannot block a UI frame or that event loop. A stopped reader leaves after its current bounded read and sort, then a stop check within 100 ms; observer restarts have a two-second throttle, so rapid epochs have a bounded number of retired readers. Disconnect clears machine records and the picker shows unavailable state. A read error also clears the last catalog and shows the typed cause.

Core frames have a 16 MiB payload bound, but that can still contain too many rows or a very long label for a frame. The observer sorts on the reader thread and shares an `Arc` slice across publication clones. The picker renders at most 50 rows, limits each displayed name, target, and state to 160 Unicode scalar values, and shows the remaining count. It does not truncate stored Core identities or use a display index as an action target.

The pure regression tests cover ordering, stable ID retention, epoch fencing, stale/error clearing, and the latest-result mailbox. A headless GPUI test covers the familiar picker section, 50-row render cap, and stale note; a Unicode test covers the label limit. The opt-in private Core observer test checks that the worker receives Core's empty catalog alongside a versioned local document, then refetches the document after a notice. Its fixture uses an explicit binary, a private socket/home, `HC_LAUNCHD_DIRECT`, checked private `server stop`, and exact-child reaping.

On macOS with Rust 1.99.0 and isolated `CARGO_TARGET_DIR=/tmp/spaceport-t02-machine-ui-target`, the focused observer suite passed 9 tests (1 opt-in ignored by default); the picker suite passed 2 tests; the opt-in observer scenario passed 1 test against `/tmp/spaceport-t00-target/debug/herdr-core`. `just check-i18n` passed 5,667 messages; `just check-file-size`, `just check-sorted`, `cargo +1.99.0 fmt --all --check`, and `git diff --check` passed. From the package root, `tools/spec.py render`, `tools/spec.py check --write-report`, and `tools/test_spec.py` passed; this validates package integrity, not application parity. The existing `VersionedDocument.value` dead-code, compact-unwind linker, and `block` future-compatibility warnings appeared; this slice introduced no new warning. No native window interaction or Windows/Linux test ran.

This is a catalog reader slice, not a completed host manager. No GUI add/connect/rename/remove action, real SSH authentication scenario, native Windows/Linux result, or A04/A05 acceptance is claimed. The legacy Device picker still has separate Herdr 1 paths that must be migrated or removed before Spaceport ships.

Follow-up review found that Core's typed refusal message could reach the frame bound, and the unavailable row formatted its whole cause. A new headless picker scenario injects a long `machine.list` refusal into the observer, confirms the row, checks the display limit, and verifies that the typed stored error retains the full message. It failed before the fix at the display-length assertion, then the focused picker suite passed all 3 tests. The picker now streams a `Display` value into a 160-character writer with an ellipsis, so neither the UI text nor an intermediate display string grows with the Core diagnostic. Format, file-size, diff, and package schema checks passed after this fix.
