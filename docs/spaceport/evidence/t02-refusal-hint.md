# T02 Core refusal hints

Pinned Core source `cd12ddd88bc11490228343291dc1096c9ed3bf77` serializes `RpcError` as JSON-RPC `error.message` with `data.kind` and `data.hint` (`crates/herdr-core/src/rpc.rs:7–43`). Its remote SSH refusal paths set actionable hints for `needs_login`, `hc_missing` and `unreachable` (`crates/herdr-core/src/machines.rs:245–391`). Before this change, Spaceport's `RefusalData` decoded only `kind`; `Error::Refused` lost the hint.

The client now retains a `RefusalHint` in `Error::Refused`. The hint is explicit to callers through `as_str`, limited to 512 Unicode characters, and kept on one line by replacing control characters and Unicode line separators. Generic `Debug` redacts the hint and `Display` keeps its prior message-only text. The existing `kind` and `message` fields and their typed error variant remain intact. The Add Device form now presents the hint as bounded untrusted text ([Add form evidence](t02-core-add-ui.md)); this does not authorize SSH trust changes.

The framed refusal fixture in `crates/sheprd-core-client/src/tests/connection.rs` first failed to compile with the missing `Refused.hint` contract under Rust 1.99, then passed after implementation. A Unicode line-separator case then failed at the one-line assertion and passed after the sanitizer covered it. The fixture checks the ordinary hint, a long multiline hint, Unicode bounds and debug redaction. `cargo +1.99.0 test --locked -p sheprd-core-client --lib` passed 56 tests with four opt-in live tests ignored; `cargo +1.99.0 clippy --locked -p sheprd-core-client --all-targets -- -D warnings` passed. Both used `CARGO_INCREMENTAL=0` and the isolated `/tmp/spaceport-t02-refusal-hint-target` target. The first test attempt used an inherited Rust 1.97 override and stopped before compilation; the pinned toolchain run is the result above. No real SSH, native GUI, or A05 host-auth scenario ran. G-MACHINE still blocks exact-ID GUI Connect/Rename/Remove.
