# Provider probe removal reachability

Read-only source audit at `e0964d26`. RM-PROVIDERS and T04 remain `in_progress`; T08 is blocked on G-OBS. No provider, account, Keychain, browser cookie, SSH host or Core state was accessed or changed. This audit does not prove A20, A29 or A30.

`crates/sheprd-usage/src/lib.rs::Usage::poll` runs from `crates/sheprd-gpui/src/window/monitors.rs::update_usage` on active-window ticks. Its worker calls `registry::all()` and each provider's `service().fetch`; `Probe` reads provider-specific sign-ins, and `CookieJar` can read browser cookies. `read` opens `Shell::connect` or `connect_wsl` for remote hosts, separate from Core's machine connection. `crates/sheprd-gpui/src/app.rs` loads usage Keychain grants on normal startup; `usage/panel.rs` can grant and retry providers. These are executable provider configuration and polling routes, not passive display code.

The same `sheprd-usage` crate exports `Host` and `Shell` to listening-port scanning, system load, dispatch and VCS checkpoint code. `crates/sheprd-gpui/src/usage/{render,panel,section,details,text,ui}.rs` also supplies status-bar, sidebar and Usage-section presentation. `config.rs` parses `[usage]`, and `control/server/hosts.rs::usage` exposes its cached readings to the local CLI. The latter currently says “No AI plan is signed in” when the entry is empty; an unavailable authoritative feed must not be reported as that fact. `sheprd-gpui/Cargo.toml` and `sheprd-vcs/Cargo.toml` depend on the crate; cloud/azure feature chains pass through it. Removing the crate by name before extracting shared pure host/shell types and replacing display input would break retained UI and still leave other excluded host readers to audit.

The specification keeps reported status, usage and rate-limit display but excludes provider probes, sign-in/configuration and a second host connection owner. Pinned Core discovery supplies reported terminal status, not a complete provider usage/rate-limit or job feed; [T08 evidence](t08-observability.md) records G-OBS. The next bounded cut must separate retained presentation from `Usage::poll` and its worker, remove grant/cookie/provider credential reads, and make unavailable values explicit in both UI and CLI while the external feed remains blocked. A source check should show no provider worker or Keychain/browser-cookie route at startup; a retained regression should show an unreported value as unavailable rather than zero or “no plan.” This is not a claim of usage parity or permission to ship a reduced product.
