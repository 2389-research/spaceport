# RM-BROWSER: service URLs use the system handler

This bounded T04 cut changes `crates/sheprd-gpui/src/browser/view.rs::open_workspace_page`: a validated `WebUrl` from the listening-port, `ports open`, pull-request, security, or orchestrator route now goes to GPUI's system URL handler on every desktop platform. The window still checks the requested endpoint before opening it. It does not add a page tab, fetch page content, or change the selected terminal. The callers in `listening_ports/render.rs`, `control/server/hosts/{ports,pr}.rs`, `security.rs`, and `orchestrator/host.rs` retain their explicit action and target checks. `WebUrl` accepts HTTP(S) only; terminal link classification and file opening remain in `terminal/links.rs`, `menu/open_link.rs`, and `window/file_links.rs`.

The service result now reports only system opening or an absent endpoint. Its CLI response still waits for a tunnel that is connecting; it no longer reports a page-tab limit for this route. Existing direct `browser` commands still have their own page-tab behavior and remain a separate deletion unit.

The headless `browser/view_tests/system_open.rs` test failed on the base commit because `open_workspace_page` returned `Tab`; after the change it records the exact `https://example.test/dashboard?view=1` URL, no new stored page tab, and the terminal still drawn. A second test rejects an endpoint absent from the window and records no URL. Existing Core terminal/chat and terminal/file link tests are retained checks, not replacements for a native browser check.

Focused verification used `cargo +1.99.0 test --locked -p sheprd-gpui --bin sheprd browser::view_tests::system_open` with a private compact target (`CARGO_INCREMENTAL=0`, `CARGO_PROFILE_DEV_DEBUG=0`): 2 passed. The same test binary passed `core_terminals::tests::chats` (3), `terminal::links::tests` (41), `chat::tests::file_links` (5), `window::file_links::tests` (7), and `control::server::hosts::tests::strict` (4). `just format-check`, `just check-file-size`, `just check-sorted`, `just check-i18n`, `python tools/spec.py render`, `python tools/spec.py check --write-report`, and the 21 package spec tests passed. The linker still reports its existing large compact-unwind section warning, and Cargo reports the existing `block 0.1.6` future-compatibility warning.

The broader RM-BROWSER graph remains reachable: `browser::{store,groups,view,native,page,preview,annotate_view,chat_pages}` and `remote_browser` still support embedded pages, annotations, and shared tab/group state; the private `browser` command and saved browser settings still exist. `Store` and group layout also back Core terminal and rich chat tabs, so deleting them now would break retained views. T03 must settle their owner before the full webview removal. G-PORT still has no verified Core forwarding route: this change does not prove a remote loopback service or replace the current SSH tunnel. T04 and RM-BROWSER remain `in_progress`; T07 stays blocked, and A27/A28/A29 remain `not_run`. No Core, real service, personal config, or native OS handler was exercised.
