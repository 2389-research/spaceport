# RM-BROWSER: page annotation cut

At parent `8b48b7d48`, `toggle_annotate` reached the command catalog and window dispatch; the browser toolbar opened a notes panel, injected `browser/annotate.js` into pages, and installed `browser/bridge.js` in local pages to expose `herdr.send`. The page IPC handler accepted picker and result posts, passed them to note delivery, and could capture WebKit screenshots for notes. The saved `notes_width_px` preference, Fluent strings, and active GPUI README described that behavior.

This cut removes that command, picker, bridge injection, panel, page-result dispatch, note screenshots, saved panel width, labels, page-note-only worker state, and tests of the deleted feature. Page IPC remains bounded for favicon posts only. The kit's `HerdrKit.send` copies a result for manual sharing; it no longer claims to queue a note. The macOS snapshot helper remains for the still-live `browser screenshot` CLI route. `browser::Store`, `Location`, generic tabs, terminal and chat presentation, explicit system URL/file opening, and service-forward UI are unchanged.

The command catalog and blank-page toolbar tests failed on the parent and pass after the cut. A stale `toggle_annotate` binding is now reported as an unknown key. A new headless page-post test sends the old `{"kind":"send"}` payload at the dispatch seam and asserts that neither pane delivery nor retained feedback receives it. That last test was added after the isolated green run and is **pending the combined integration run**. Source inspection shows `apply_page_post` only calls `Favicon::parse` and `page_favicon`; `with_initialization_script` and the annotation modules are absent.

Isolated branch checks: `cargo +1.99.0 check --locked --offline -p sheprd-gpui --all-targets` passed with no source warnings after orphan cleanup. `cargo +1.99.0 test --locked --offline -p sheprd-commands page_annotation_command_is_absent` passed 1/1.
