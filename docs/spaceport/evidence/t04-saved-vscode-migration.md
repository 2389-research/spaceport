# T04/RM-IDE: saved VS Code tab migration

At parent `5b3821b5`, `crates/sheprd-gpui/src/browser/store.rs::Store::load` parsed the whole `browser-tabs.json` file, then `Store::with_tabs` restored old VS Code editor tabs. `window.rs::tick` could therefore reach `ensure_code_page` and the VS Code server path on startup without a new user action. Both saved `place` spellings, `"code"` and `"code_group"`, map to `Editor::VsCode` in `browser/editor.rs`. This cut keeps that parser so an old entry cannot invalidate the whole file, then drops only `Place::Editor(Editor::VsCode)` during in-memory restoration. It leaves px0, web pages, Core terminal tabs and separate read-only `Location::Code` tabs at their saved IDs.

`Store::with_tabs` now reserves the next ID from **all** parsed tabs before filtering. A saved group pick can still name a discarded tab; a later tab must never inherit that ID and appear in its place. This reservation also covers already-discarded orchestrator tabs. For a saved maximum of `u64::MAX`, `restore_tab` refuses a new tab instead of wrapping. The loader does not rewrite the person's file; a later source-removal cut must keep legacy parse support or provide a proved state rewrite. `OpenCode`, group/menu entries, code-server workers, settings and new VS Code tab creation remain reachable for their next coherent cut.
