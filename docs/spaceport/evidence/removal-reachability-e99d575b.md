# Removal and retention reachability at `e99d575b`

This source snapshot covers all 19 entries in [the removal plan](../plan/removals.json) at
commit `e99d575b` (`chore: Add a shape guard for artifact-host task writes`, committed
2026-11-25). It supersedes the [snapshot at `7f15ad1a`](removal-reachability-7f15ad1a.md) for
current source navigation; every earlier record stays intact as history. The tree has been
renamed since those records were written: every workspace crate is `spaceport-*` but the
`embed-resource` stand-in, no `sheprd-*` crate remains, and the app is `crates/spaceport-gpui`.
A label copied from an older snapshot would therefore name files that no longer exist, which is
why each row below was re-derived at this commit. **Present** means a live source entry point
still reaches the named feature. **Absent** means the named source route and its listed build
entry points are gone. **Partial** means some routes are gone while others remain, or a retained
path still depends on the old owner. These are reachability labels, not acceptance results.
Unless fully qualified, paths below start at `crates/spaceport-gpui/src/`. Each label comes from
grepping that family's markers over `crates/`, `scripts/`, the mobile workspace and the
workspace manifest at this commit, with test sources excluded, so a hit is a production route
rather than a fixture. Where a family is absent, the absence test that forbids its return is
named as the boundary.

## Proof limits

This pass inspected current source, manifests, absence tests and linked evidence. It did not build
or launch the app, Core, a remote host or a release package. The absence tests named above were
run as text checks (`python3 -m unittest` over `scripts/release/tests/`), which proves the routes
they name are gone from these files; they do not prove absence of behaviour. The [native platform
record](native-platform-results.md) covers earlier private macOS fixtures but no final Spaceport
desktop qualification, and Windows and Linux native runs remain absent. All eight gaps stay open
(G-CHAT, G-PORT, G-FILE, G-MACHINE, G-LINK, G-OBS, G-RELEASE, G-PLATFORM). [The acceptance
record](../plan/acceptance.json) has four passing `herdr1` legs (A01, A10, A45, A47), one blocked
`core` leg (A04) and `not_run` everywhere else. T04, T08 and T12 are `blocked`; T11 is
`not_started`. The plan's `audit_status`, task statuses, gaps and acceptance results remain
authoritative registers and are unchanged by these source labels.

Two residues sit outside every family above and are recorded here rather than fixed by a
read-only pass: `crates/spaceport-settings/config-gpui.example.toml:274-275` still lists
`git_menu` and `toggle_annotate` among the commands that are unbound by default, although
neither is in the catalog, and `:473-475` tells a reader that **Settings → Cloud devices →
Container** edits the container engine key although no settings page names a cloud device.
`main.rs:135` also keeps a dangling `// Git status, without GPUI.` comment above an unrelated
import, left by the removed VCS crate.
