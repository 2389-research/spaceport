# T07 binary file route audit

T07 remains blocked on G-FILE and G-PORT. This is a source/schema audit against pinned herdr-core `cd12ddd88bc11490228343291dc1096c9ed3bf77`, not a Spaceport file-interaction scenario. No personal Core or user file was read or changed.

Core's `terminal.put` accepts a machine-qualified terminal address, a basename and at most 8 MiB of base64 bytes. `remote.rs` includes it in the exact-terminal remote route. `put.rs` stages the bytes under the terminal's private state directory using a sanitized basename and a new non-overwriting file; that directory is removed with the terminal record. The returned path is on the terminal's machine. Transferring bytes and submitting that path to the program are distinct effects. This is a candidate for bounded drag/drop or image attachment, subject to A25 on local and remote fixtures.

Spaceport now has a typed, bounded `Core::terminal_put` client call. A scripted peer test checks the exact qualified target, base64 binary payload and parsed path; separate tests reject over-limit input and absent method before dispatch. The private two-Core fixture staged `[0, 255, 65]` in a live remote terminal and read the same bytes from Core's returned private path. This verified the Core route on macOS with a test relay, not app drag/drop, a real SSH host or Windows/Linux. The staged path is only returned; the client sends no terminal input. A25 stays not_run until the UI and local/remote behavior are exercised.

`file.write` accepts up to 8 MiB of base64 bytes on a named machine. In `files.rs`, it follows symlinks, writes a temporary file beside the target and renames it over the target; it can overwrite an existing file. That policy needs explicit UI target, overwrite and symlink decisions before use. `file.read` returns UTF-8 lines only; it rejects non-text bytes and caps the JSON reply. `machine.exec` can return bounded base64 stdout, but it is a one-shot command with truncation and timeout, not a general file transport contract. None of these methods establishes binary download, large-transfer, cancel-after-submit or ambiguous-outcome parity. A timed-out write may have taken effect and must not be retried blindly.

The smallest external dependency for full retained general binary transfer is a Core-owned binary read/download route on an exact machine and path, with bounded or chunked bytes, a defined symlink policy, cancellation/lifetime and clear post-submit outcome. If uploads above Core's 8 MiB inline cap are required by the retained UI, that route also needs bounded upload chunks and an explicit overwrite precondition. This note does not prescribe an RPC name or a parallel Spaceport transport. A25/A26 remain **not_run** until private local and remote scenarios cover attachment, upload/download, overwrite, symlink, cancellation and uncertainty. G-FILE stays open.
